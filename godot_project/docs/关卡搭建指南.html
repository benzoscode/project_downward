《downward》关卡搭建指南

面向策划 · 无需写代码 · 所有联动靠"拖积木 + 填参数"完成 · 配套引擎 Godot 4.7

工作流程新建房间画 Tile 节点结构放机关传送点 重生与检查点自检运行红线

核心思想：一切都是积木

关卡 = 一个 .tscn 场景。场景之间完全独立，靠"出口积木"互相指向就能来往。 机关之间用字符串 ID 联动（按钮填 target_id，门填同名 listen_id 即开）。 你不需要改任何代码，也不需要登记任何清单。

  1. 复制房间模板（或装修灰盒骨架）
  2. 画地形与装饰 Tile
  3. 拖入机关积木、填 ID 连线
  4. 放入口/出口/检查点
  5. F6 运行当前场景试玩，跑一键验证

1. 新建一个房间

  1. 在 FileSystem 里找到 scenes/templates/room_base.tscn，右键 Duplicate（复制）。
  2. 把副本移到 scenes/rooms/，改名为你的房间名，如 room_05.tscn。不需要在任何地方登记——其他房间的出口可以直接指到它。
  3. 双击打开，选中根节点（RoomBase），Inspector 可见参数：
    参数作用默认
    editor_brightness编辑器里的显示亮度（只影响搭建时）0.45 灰
    game_darkness运行时黑暗程度（越小越黑；灰盒是 0.3，正式洞窟建议 0.05）0.05
    player_input_delay玩家输入延迟秒数（第 9 房间致幻机制用 0.8，其他房间 0）0
  4. 选中 Camera2D 节点，把 limit_right / limit_bottom 改成你房间的像素尺寸（宽 = 格数 × 16）。相机会被自动钳在这个范围内。
更快的方式：room_01~12 已有灰盒骨架（40×17 格小房间，结构已含出入口与能力门），直接在灰盒上装修最省事。注意灰盒里出入口位置和能力门结构（高墙/窄缝/钥匙门）不许动（见红线）。

2. 画 Tile（地形与装饰）

房间里有三个 TileMapLayer，各画各的，不要混用：

层画什么特性
TileMapTerrain地面、墙、平台——一切会挡住玩家的东西带碰撞 + 挡灯光
TileMapDecor草丛、钟乳石、水晶簇等装饰无碰撞，纯好看
TileMapMechanismMarkers机关占位草稿（规划记号用，没有任何代码读它）无碰撞；会在游戏里显示——草稿打完记得清空或把层 visible 关掉

操作

  1. 选中 TileMapTerrain 节点 → 下方出现 TileMap 面板。
  2. 面板顶部按 source 切换图集（见下表），点选图块后在场景里刷。
  3. 装饰切到 TileMapDecor 用同样方式画。

图集速查（source 编号 = TileMap 面板顶部分页）

source内容碰撞
1泥土苔藓：苔藓边/拐角/点缀（行0-1）、纯泥土 fill（行2）、脉纹水晶（行3）✔
2石质：石墙/藤蔓墙/石板/石刻面砖✔
5石砖：(0)砖体 (1)砖顶 (2-4)草顶砖 (5-7)裂纹砖✔
3装饰 16px：水晶簇/藤蔓/钟乳石/石笋/岩石/石拱✘
4装饰 32×32：石柱、苔藓石柱✘
6草丛装饰 01~07✘
7水面静态瓦片（只负责好看，水的减速效果靠 water.tscn 积木）✘
8-11水体动画瓦片：平静 9 帧 / 平静长循环 18 帧 / 波浪 01、02 各 16 帧——刷上自动播放✘
source 0 是早期占位图块，新关卡请用 source 1/2/5。

3. 房间的节点结构

RoomBase（根，调亮度和致幻参数）
├── CanvasModulate        黑暗基底（自动，别动）
├── Background            洞窟背景图
├── TileMapTerrain        ← 地形画这里
├── TileMapDecor          ← 装饰画这里
├── TileMapMechanismMarkers
├── Mechanisms            ← 机关积木都放这里
├── Characters            ← Boss/老鼠等（玩家不用放，自动生成）
├── Lights                ← ambient_light 环境光源放这里
├── SpawnPoint            出生点（兼默认入口）
├── Entrance_default …    入口标记（Marker2D）
├── Exit_to_xxx           出口积木（room_exit.tscn）
└── Camera2D              相机边界（limit 四值）
新机关拖进来时挂到 Mechanisms 下，保持结构统一，别人接手好找。

4. 放置机关

联动规则（唯一要记的）

触发源填 target_id，接收方填同名 listen_id，即完成连线。一对多、多对一都可以。 机关状态全游戏保留：玩家死亡后，开过的门还是开的（这是设计，不是 bug）。

例：想让按钮开门 → 按钮 target_id = door_a，石门 listen_id = door_a。完事。

积木速查（scenes/interactables/）

积木用途关键参数
lion_button狮子头按钮，E 键触发target_id；one_shot（一次性/切换）
stone_door石门（32×48），向上滑开listen_id；start_open；tint 调色
key_door钥匙门（金色），拿到钥匙才开免配置（动画 tween_duration 可调）
light_crystal光敏水晶：灯照 2s 激活广播target_id；charge_time
pressure_plate压力板：踩下触发、离开解除target_id；mouse_only（小板仅老鼠）
dual_button_door双按钮门：全部触发才开listen_ids 数组；close_delay
trigger_relay滞后组件：触发后延迟 N 秒再发input_id → output_id；delay
color_button + sequence_controller顺序机关：按颜色顺序按下才触发按钮配 sequence_id+color_id；控制器配 expected 序列+target_id
alternating_platform交替平台：A/B 组按周期显隐period（默认 1.5s）；group_b
lever_platform摇杆平台：按住 E 平台移动move_offset；move_speed；dwell_time
fake_platform虚空平台：看着能踩，直接穿过无
grass_cover草丛光透：灯照变透明露暗道无（纯视觉，通道本来就能走）
spikes地刺：碰即死回检查点无（贴地放，origin 在瓦片中心）
water水体：减速 50%+半透明size（直接拖，origin 左上角）
ladder梯子：W/S 攀爬，空格翻出height（px，origin 在底部；顶端高出平台半格）
pickup道具拾取：lamp/boots/whistle/三宝石/keyitem（图标自动匹配）
chest宝箱：E 开启发道具（一次性）item
ambient_light环境光源：熔岩缝/荧光苔，站在里面关灯也会被 Boss 发现radius_tiles（格）

5. 传送点（出入口）

入口 = 一个 Marker2D

选中根节点 → Add Child Node → Marker2D → 命名 Entrance_xxx，摆到落点。 约定：Entrance_default 是默认入口（没指名时落这里，再没有就落 SpawnPoint）。

入口/出口必须挂在根节点直接子级（和 SpawnPoint 平级），不要放进 Mechanisms 等子节点里——落位查找只认根节点直接子级，挂错层会静默找不到，玩家落到 SpawnPoint 甚至原点，只有一条不显眼的警告。

出口 = room_exit 积木

  1. 把 scenes/interactables/room_exit.tscn 拖进房间，挂到根节点下（与入口标记平级），摆到门洞/通道口位置。
  2. Inspector 里 target_scene 点文件选择器直接选对面的 .tscn。
  3. target_entrance 填对面入口 id（对面是 Entrance_default 就留空 default）。
  4. 需要触发区更高/更宽：展开它的 CollisionShape2D 调矩形尺寸。编辑器里出口显示青色框 + 目标名，一眼可辨。

往返

想能走回来，就在对面房间也放一个指回来的出口。双向靠人肉配对，引擎不强制——建议每配完一条边立刻试走一个来回。

过渡节奏固定为 0.4s 渐出 + 0.15s 黑场 + 0.4s 渐入，无需配置。想挡住玩家"以后再来"：把石门/钥匙门/高墙放在出口前面，出口本身不做条件判断。

6. 重生点与检查点

机制行为你要做的
SpawnPoint房间自带的出生标记，兼兜底入口摆到出生位置（灰盒已摆好）
自动存档玩家每进入一个房间，入口即成为检查点什么都不用做
checkpoint.tscn房间中部的存档点：触碰存档，死亡回这里，旗子变金色拖一个到刺坑阵前/Boss 房前等位置
死亡表现同房间死亡：原地回检查点；跨房间死亡：重载检查点所在房间。机关状态保留什么都不用做
相机已做瞬移处理：进房间和重生后镜头直接对准玩家，不会有"摇过去"的过程。

7. 自检与运行

操作效果
F6运行当前房间（玩家自动生成在默认入口）
F5从 room_01 开始完整跑（入口场景是 scenes/main.tscn）
一键验证godot_project 目录下执行 powershell -File tools/run_verify.ps1，末尾出现 VERIFY PASSED 即全部通过

开局位置怎么改

F5 的出生点 = scripts/main.gd 里 goto_room(...) 指定的场景 + 入口标记。 想挪位置：打开 room_01.tscn，把 Entrance_default 拖到目标点即可； 想换开局房间（比如调试直接进 room_05）：找程序改 main.gd 里那行的路径和入口 id。

常见报错

现象原因与处理
出口不触发target_scene 没选文件 / 触发区没盖住通道口
落地位置不对对面缺 Entrance_xxx 标记，或 target_entrance 填错了 id
门不开按钮 target_id 和门 listen_id 没对上（区分大小写）
VERIFY 变红提到连通性动了灰盒的出入口/能力门结构，或出口指向了不存在的文件
玩家在房间里不出现你自己又放了一个 Player——删掉，玩家是自动的

8. 红线（动了会出事故）

① 灰盒房间的出入口位置、5 格高墙、老鼠窄缝、钥匙门不许改——连通性和能力门靠自动测试兜底。
② 不要把机关跨房间用节点路径相连（NodePath 拖引用）——跨房间联动只用字符串 ID（MechanismBus 是全局的，4 房按钮开 5 房门就是这么做的）。
③ 不要手改 assets/tiles/ 下的图集 PNG 和 tileset_cave.tres——布局由脚本生成，要加瓦片找程序。
④ 不要在房间里放 Player 节点；不要删 CanvasModulate / Camera2D。
除此之外随便折腾：装饰随便画、机关随便组合、参数随便调——所有积木默认值都是能直接跑的。
